# hermes-agent ↔ Buddy — the piece-by-piece map

*Written 2026-11-02. Hermes read from a full source clone of `NousResearch/hermes-agent` at `c8f5750a` (main) — 415 `agent/` modules (~150k LOC), 374 `tools/`, 345 `gateway/`, ~640 `hermes_cli/` modules, ~7.5k test files — via four parallel source audits (agent core, tools/approval, gateway/cron/learning, CLI/ops). Buddy read from THIS repo local `main` at `c17bfdc` (v0.67.0) — the updated local, per the ask; every v0.66-era row the P0-hardening wave changed is re-judged here. Verdicts: ✅ parity · 🟡 partial · ❌ not implemented · 🚫 not adopted by design · ➕ Buddy-only.*

## 1. What each side IS

**Hermes** is a *resident companion agent*: a Python daemon (`gateway/run.py`, a 5.2k-line facade over phase modules) installed as a systemd/launchd/s6 service, answering on ~29 messaging-platform plugins (Telegram, Discord, Slack, WhatsApp, Signal, Matrix, iMessage, IRC…) from one process, with all durable state in `~/.hermes/<profile>/state.db` (SQLite WAL) + JSON files. Provider breadth is the headline: ~37 built-in provider profiles over 4 wire transports, a second "auxiliary" LLM plane (~30 modules) for side jobs, and six terminal backends (local/Docker/SSH/Modal/Daytona/Vercel). MIT; most of what makes it powerful needs accounts/keys (the Nous Portal anon free-tier is the keyless door). Its own SECURITY.md states the posture: *the OS is the only boundary against an adversarial LLM* — every in-process gate is accident prevention.

**Buddy** is a *terminal co-pilot*: zero-dependency Node CLI, keyless 4-gateway chain + local ollama, one session does the deciding and the doing. v0.67.0 adds the P0 hardening: a self-edit firewall over the `.buddy` control plane, headless default-deny for risky tools, router fast-fail with named park times, and self-update integrity (ancestor check). Its autonomy plane (channels = event-driven, goals = clock-driven) lives inside a session, not a daemon.

## 2. Component inventories

## 4. NOT implemented in Buddy (honest list, keyless-filtered)

1. **Daemon residency with durable outbound delivery** — the third reference in a row (dsh, OpenHands, Hermes) where the single big gap is the same: a process that owns state across restarts. Hermes' delivery ledger (obligation rows redelivered after a crash) is the most adoptable slice: goals + channels + eventslog already hold 80% of the parts.
2. **`execute_code`-style programmatic tool calling** — collapses multi-step pipelines into zero-context-cost turns; Hermes' kernel is local and token-gated, so nothing about it needs a key.
3. **FTS-style session search** — item 14; the recorder is append-only JSONL, so the index is lazy work, not a re-architecture.
4. **The autonomous half of the learning loop** — a post-turn review fork ("save or update a skill/memory?") is prompt-shaped and keyless-feasible; Buddy currently learns only when told.
5. **Per-surface toolsets and progressive disclosure** — matters only with many surfaces; N/A until channels grow.
6. **Messaging platforms** — a bot token per platform; by-design no.
7. **Multi-account credential pooling / provider profiles** — needs accounts; by-design no.

## 5. WRONG or overstated — full-source corrections to the README-level parity map

1. **"FTS5 session search with LLM summarization" — the LLM part is not in the search tool.** `tools/session_search_tool.py` docstring: "No LLM calls — every shape returns actual DB messages." LLM summaries exist only as compaction handoffs and session titles. The parity map's FTS5 ✅ was right; the summarization was generous.
2. **"Honcho dialectic user modeling" — not bundled.** It is an external catalog plugin (`hermes plugins install honcho`); the in-repo memory providers are byterover/retaindb examples. The README headline reads as built-in.
3. **"Failover" — real machinery, but the word never appears in the README** (it lives on the docs site), and fallback is turn-scoped: the primary is restored next turn, not migrated.
4. **"40+ tools" marketing → 73 statically registered** (+ unbounded MCP/plugin/bridges) — confirmed, and larger than claimed.
5. **Serverless hibernation (Modal/Daytona/Vercel) — real but guard-free:** dangerous-command prompts are skipped entirely on those backends (`_should_skip_container_guards`); trust moves to the vendor sandbox. The "costs nothing when idle" story has a security asterisk the SECURITY.md documents and the marketing buries.
6. **Correction to my own v0.66-era row:** the parity map called Hermes approval "command approval patterns" — full source shows a 10-module stack with unbypassable floors, an import-frozen yolo, a smart-guardian LLM, and gateway block-wait approvals. Buddy's v0.67 headless default-deny closes the one door Hermes leaves configurable (`unattended_mode: approve`).
7. **Correction to this map (row 21):** "zero telemetry" — false. Reading local Buddy source for the mirror map (`docs/buddy-deep-map.md`) found `src/telemetry.js` (v0.53.0, §11): an opt-in OTel/JSONL exporter over the events.jsonl audit trail, default-off, torn-line-safe cursor, operator-chosen endpoint. Same opt-in contract as Hermes', different destination owner. Verdict ➕ → ✅.

## 6. The verdict

Hermes is what Buddy would be with accounts, a daemon, and 150k more lines: the resident companion vs the $0 terminal tool. The hardening wave flipped the verdict column on rows 8/9/4/18 — where the v0.66 map showed gates, Buddy now shows structure (default-deny unattended, an immutable control plane, a fast-fail brain, rollback-proof updates). Highest-value adoptions, all keylessly feasible: **(1)** the durable-delivery slice of the gateway for goals/channels, **(2)** `execute_code`-style programmatic tool calling, **(3)** FTS-style session search over the JSONL recorder, **(4)** the post-turn learning nudge. Everything else is either at parity, needs keys by design, or is heavier machinery than a zero-dependency CLI should want.
