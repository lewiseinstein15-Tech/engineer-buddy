# OpenHands ↔ Buddy — the piece-by-piece map

*Written 2026-11-03. OpenHands read from full source clones of BOTH repos that now carry the name: `OpenHands/OpenHands` at `99439d7e` (main, 2026-11-02) — which is **Agent Canvas**, npm `@openhands/agent-canvas` v1.34.0, a React 19 + TypeScript monorepo (~158k TS lines: 93k components, 25k hooks, 22k api clients, 8k routes, Electron shell, Helm chart) — and `OpenHands/software-agent-sdk` at `f5ba2179` (main, 2026-11-02) — the agent itself, ~142k Python lines across `openhands-sdk` (316 files, 84.5k), `openhands-agent-server` (98 files, 36.5k), `openhands-tools` (97 files, 17.8k), `openhands-workspace` (14 files, 3k), plus 798 test files. The automation backend is a third artifact entirely: the `openhands-automation` PyPI package, installed by Canvas' Dockerfile but not present in either audited repo — an audit boundary recorded in §5. Buddy read from THIS repo local `main` at `218b29f` (v0.69.0 — waves 0–5 of the serve rebuild shipped). Verdicts: ✅ parity · 🟡 partial · ❌ not implemented · 🚫 not adopted by design · ➕ Buddy-only.*

## 1. What each side IS

**OpenHands** is a *platform for agents*. The pendulum has swung all the way to architecture: Canvas (the UI, which by its own architecture doc is "not responsible for executing agent actions, providing the sandbox, hosting LLM credentials, or running automations") talks REST to the Agent Server (a FastAPI runtime that owns conversations, events, secrets, and per-conversation Docker runtimes), which runs the SDK agent (event-sourced, branchable conversations, LiteLLM behind an explicit fallback strategy, risk-scored confirmation, Claude-Code-shaped hooks) — and Canvas can just as well drive Claude Code, Codex, Gemini CLI, Pi, or OpenCode over ACP (JSON-RPC on stdio, spawned by the server). Automation (cron + webhooks into Slack/GitHub/Linear) is a separate always-on service. Apache-2.0; it assumes keys everywhere — LiteLLM profiles, ACP CLI credentials, PostHog analytics (consent-gated).

**Buddy** is a *terminal co-pilot*: zero-dependency Node CLI, keyless 4-gateway chain + local ollama, one session does the deciding and the doing. As of v0.69.0 it carries the serve rebuild's waves 0–5: the control-plane firewall, the serve daemon (lease / control socket / delivery ledger / restart guard), goals catch-up durability, unattended run-token allowlists, and cursor-built session search. Its autonomy plane (channels = event-driven, goals = clock-driven) lives inside a session, not a daemon.

## 4. NOT implemented in Buddy (honest list, keyless-filtered)

1. **Risk-scored security analyzers** (LLM analyzer, grayswan, ensemble) — the LLM halves need a scorer model; the **shell-AST parser** is keyless and adoptable as an extra danger-tier input.
2. **LLM-summarizing condenser** — needs a model call per condensation; adoptable the day a keyless summarizer earns its tokens (same verdict as the Hermes row).
3. **Branching event store** — Buddy's append-only JSONL is load-bearing for the sessionsidx cursor and crash-safety; a branch layer would trade those for fork-first-class. Left out by design.
4. **Per-conversation Docker runtimes + remote/cloud/apptainer workspaces** — accounts or heavy infra; `/sandbox` + `containers` cover the local need.
5. **Automation Server** (webhook triggers, Slack/GitHub/Linear, always-on) — the daemon-gravity wave refuses it; `channels` + `goals` stay in-session.
6. **ACP hosting of third-party agents** — Buddy would have to stop being the agent. Refused.
7. **Critic, stuck detector, ask_oracle/tom_consult consults** — all model-backed per-turn costs; the stuck detector is the one with no token bill and the clearest case for adoption.

## 5. WRONG or overstated — full-source corrections to the README-level parity map

1. **"MCP: 🟡 via ACP agents" is no longer true.** The SDK ships a first-class MCP client (`openhands/sdk/mcp/`: client, config, oauth, tool definitions), and `agent/base.py` imports `MCPClient`/`MCPServer` directly. OpenHands talks MCP natively.
2. **"Approval gates: 🟡 sandbox-first posture" is understated.** The SDK has a full in-process gate: `SecurityAnalyzerBase` → risk levels → `ConfirmationPolicy` (AlwaysConfirm/NeverConfirm/ConfirmRisky), confirmation mode with pending-action queues, and hooks that can block a user prompt outright. "Sandbox-first" described the 2025 architecture, not this one.
3. **"Multi-agent: ✅ Agent Server hosts many" needs precision.** The server hosts many *conversations*; each conversation runs the configured SDK agent or one external ACP CLI. It is not many cooperating agent kinds in one task — that shape (Buddy's `orchestrator.js`) is the thing OpenHands decomposes differently.
4. **"Memory: conversation history survives" is weaker than the source.** Persistence is event-sourced — one JSON file per event plus `base_state.json`, with branch/leaf navigation and a lazily-maintained View. That is a conversation database, not a surviving transcript.
5. **"Sandboxing: ✅ Docker per conversation" is accurate but now the smaller half** — the `openhands-workspace` package adds remote_api, cloud, agent_sandbox, and apptainer (HPC) backends behind one interface.
6. **The name is a trap for mappers.** Cloning `OpenHands/OpenHands` main yields a React application ("Agent Canvas"); the agent core lives in `OpenHands/software-agent-sdk`, and the automation backend is installed from PyPI (`openhands-automation`) without source in either repo. Any parity row derived from the main README alone inherits that blind spot — this map's pins (`99439d7e`, `f5ba2179`) are the correction.
7. **"Environment doctor: —" stands.** Canvas has a backend health-store, but there is no workspace ECC sweep to compare with `buddy doctor`.

## 6. The verdict

OpenHands spent its re-architecture budget becoming the *host* — Canvas, server, workspaces, automation — and rebuilt the agent as a clean SDK underneath. The two ideas worth stealing are in that SDK: the **conversation as a branching event store with a lazily-maintained View** (context engineering as a first-class subsystem, condensation as an event), and the **risk-analyzer / confirmation-policy split** — the honest version of what `/yolo` collapses into one switch. The stuck detector costs nothing and should be adopted. What Buddy refuses is the rest of the pendulum swing: three repos, an always-on automation service, PostHog, and a 93k-line UI watching agents work — because Buddy's contract is to *be* the agent, keyless, in the terminal where the work is. The lease row is the quiet headline: OpenHands and Buddy independently arrived at the same ownership discipline (lease, TTL, proof-of-ownership, loser exits) at two different scales — convergent evidence the serve wave built the right thing.
